# v0.3 context-gate Decision Record

status: "terminated"

## 1. Background

**Triggering event:** v0.2.0 收尾（`docs/decision/v0.2.0-closeout.md`）已经证伪“置信证据层优于 AI 直读 diff”。剩下唯一还没被正面检验的价值假设是：decay 真正的位置不是“当 reviewer”，而是当一个**确定性的 diff 外上下文提供者**——给定一个 diff，把 AI 单看 diff 看不到的原始代码（被改函数的调用方、同 trait 的其他实现、覆盖该路径的测试、依赖被改状态的 assert）确定性地抽出来喂给 AI，从而让 AI 的 review 比 AI 单看 diff 更好。

**Gate（预注册）：** 在冻结的 frozen-v1 cohort 上，treatment（AI + decay 抽取的 diff 外上下文）相对 control（AI 单看 diff，即已判的 ai-baseline-v1，missed=8、weak_only=0、precision@top3=61.62%、judged=34）必须把 `missed_high_risk_count` 砍到 ≤4，且 weak_only ≤5、precision 不跌破 56.62%——否则判 Path B。

**Constraints:** frozen-v1 的 diff 用 `--unified=80` 生成，control 已经看到每个 hunk 上下各 80 行**同文件**上下文；treatment 的边际贡献只剩**跨文件**上下文。

## 2. Decision

**We decided:** 终止 decay 产品（`status: "terminated"`）。不再 build 新的方向，不再 reframe。

### 检验过程与为什么 treatment 不能赢

在 build 抽取器、花约 34 次 AI-with-context 生成 + 约 34 次 judge 调用之前，先做了一个便宜的前置诊断：treatment 只有在“control 的漏报是缺跨文件上下文导致的”时才可能降 `missed`。我们把 control 的全部 8 个漏报对照 judge 自己的 note 逐条审了一遍（`eval/reports/v0.3-context-gate.md` 有完整表格），结论是 **8 个漏报里 0 个是 diff 外上下文能修的**：其中 7 个是**分类标签错配**——AI 其实**从 diff 就找到了风险机制和修复位置**，只是给它打的 signal id 跟裁判的 `primary_signal_ids` 不一致；剩下 1 个（hyper-4011）是缺**外部规范知识**（RFC 9110 trailer 大小写不敏感），而 RFC 文本既不在 diff 里、也不在 repo 里。喂跨文件的调用方/trait/测试源码，**既不会改变 AI 对一个它已经找到的风险所打的标签，也变不出一份不在仓库里的 RFC**。因此 Path A 的主杠杆 `missed` 在构造上就降不下来，treatment arm 没有运行的价值——跑一个有噪音的单样本，证据强度还不如这份逐 case 的机制审计。

## 3. 为什么是 terminated 而不是再 narrow 一次

这是 decay 第 4 个被否的价值假设：复杂度退化检测 → 事实证据层 → 置信证据层（v0.2.0 证伪）→ diff 外上下文提供者（本次前置诊断证伪）。按 know 规则，连续 reframe ≥2 次通常意味着 core thesis 从一开始就没站稳，而不是“在精进”。更根本的病根:这个项目从头到尾是**先有解、再找问题**——做了一个工具，然后到处找它能用在哪——而**至今没有一个真实 dogfood fixed case**(作者本人用它真正逮到并修掉过一次的记录)。两年级别的投入,零验证痛点,加上正面冻结实验连续两次把价值假设打穿,继续 narrow 只是换个更好听的故事。诚实的判断是停。

## 4. What survives

- **作为产品/独立 thesis:** 不 survive。"静态工具产出 review 价值"和"静态工具当 AI 上下文底座"都已被这套冻结评测否掉。
- **作为可复跑的证据资产:** `eval/head-to-head/`（冻结 prompt/schema/manifest + 34 份 ai-baseline 判定）、两份决策（v0.2.0、v0.3）、以及 head-to-head 评测骨架，留作"AI 时代 review 形态"判断的一手证据，不删。
- **作为方法教训（最有价值的部分）:** 先验证再 build、先定位再动手、对负结果诚实——这些教训本身比任何一版 decay 都更值得带走。

## 5. Status

**terminated** — decay 产品方向终止;评测资产与决策记录保留作证据,不再开发新方向、不再 reframe。
