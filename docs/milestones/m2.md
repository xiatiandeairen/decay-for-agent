# M2 — v0.1.1 Fact Evidence Baseline

## 1. Goal

### Definition of Done

完成 v0.1.1 fact evidence baseline：

- `decay diff <git-ref>` 能输出可追溯的 fact evidence sections。
- 外部 PR validation harness 能跑通真实开源 PR case。
- 至少 10 个高质量 case 完成人工 ground truth / decay evidence / comparison。
- 输出中明确标注当前指标的真实价值边界，避免把弱扫描信号包装成主风险。
- 打 `v0.1.1` tag，作为 v0.2.0 semantic layer 的对照基线。

### Value Target

证明纯静态扫描的可用边界：

- 哪些场景能真实发现有价值问题。
- 哪些场景适合静默。
- 哪些信号只是 supporting context 或无效堆砌。
- 哪些高价值风险必须交给 v0.2.0 semantic layer。

### Key Hypothesis

- **Hypothesis**: fact evidence layer 可以提供部分真实 PR review 价值，但不足以稳定识别 API/protocol/behavior 语义风险。
- **Type**: product boundary validation
- **Validation method**: 用真实开源 PR 和 mxcore-proposal 场景进行 ground truth 对比，统计 useful / plausible / noise / missed，并把结论沉淀为 v0.2.0 的 baseline。

## 2. Plan

### Delivered

- done: 外部 PR validation harness，包含预注册 case、runner、ground truth、comparison、summary。
- done: 10-case judged baseline，覆盖 hyper 和 ripgrep 的 bugfix / feature / refactor / negative control。

### Go/No-Go Criteria

| Dimension | Criterion |
|-----------|-----------|

### Measured Baseline

10-case baseline:

```text
precision_at_top3 = 65%
actionable_pr_rate = 60%
negative_control_silence_rate = 100%
missed_high_risk_count = 2
noise_top3_count = 3
history_only_false_positive_count = 0
```

### Effective Fact-Only Scenarios

- 默认值 / 配置值 / 命令参数变化。
- 明确危险构造新增，例如 `unsafe`、`unwrap`、`expect`、`panic!`。
- 明确扫描 pattern 的协议 header 风险，例如 Host header authority -> host/port。
- build / dependency / feature surface 变化。
- docs-only、test-only、mechanical clippy/refactor 的静默。

### Weak Or Invalid Standalone Signals

- `mixed_concerns`：多数只是范围描述，单独行动价值弱。
- `blast_radius`：说明范围大，但不能说明风险是什么。
- `touched_existing_risky`：容易把旧复杂度债务包装成本次风险。
- history evidence：只能作为 context，不能单独证明本次 diff 风险。
- moved/refactor 中的新增表象：如果没有 identity / move-aware 判断，`panic_like_added` 或 `public_api_added` 容易误报。

### Decision Path

- **Pass**: fact evidence layer 已提供真实但有限的价值，进入 M3 semantic evidence。
- **Do not expand**: 不继续用更多静态扫描规则堆高输出量。
- **Next focus**: semantic finding schema、weak signal suppression、API/protocol/behavior high-value missed scenarios、20-case benchmark。

### Risks

Dependencies: 高质量 PR case、人工 ground truth、可复跑 eval harness、稳定 fact evidence schema。

Risks:

- 10-case 样本仍小，不能夸大为普遍产品成功。
- Host header pattern 属于明确场景命中，不等于通用协议语义理解。
- negative control 当前表现好，但 semantic layer 增强后必须继续守住静默率。

## 4. Outcome

M2 completed on 2026-05-13.

Conclusion:

- fact evidence layer is valuable for explicit structural risks and negative-control silence.
- fact evidence layer is insufficient for API design, protocol behavior, and behavior-gate semantic risks.
- v0.2.0 should build semantic selection above fact evidence, not replace fact evidence and not become subjective merge scoring.
