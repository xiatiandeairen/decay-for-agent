# M3 — v0.2.0 Confidence Evidence

## 1. Goal

### Definition of Done

`decay diff <git-ref>` 输出给 AI 消费的置信证据层。

每条 fact evidence 必须尽量包含：

- `confidence`
- `value`
- `category`
- `kind`
- `source`
- `subject`

约束：

- 保留底层 fact evidence。
- 不输出面向人的 `Semantic findings`。
- 不生成 `claim`。
- `mixed_concerns`、`blast_radius`、history、纯 `touched_existing_risky` 必须标为 supporting/context，而不是 direct。
- 不输出 merge recommendation。
- 不声明 bug。

### Value Target

相对 v0.1.1 fact-only baseline，提升 Top risk 的行动价值：

```text
precision_at_top3: 65% -> >= 75%
actionable_pr_rate: 60% -> >= 70%
negative_control_silence_rate: 100% -> >= 90%
missed_high_risk_count: 2/10 -> <= 1/20
weak_only_top_risk: 3/10 -> <= 2/20
```

### Hypotheses

- **H1**: confidence/value labels 能让下游 AI 区分 direct evidence 与 weak/context evidence。
- **H2**: direct semantic evidence 能减少 API/protocol/behavior 类高价值漏报。
- **H3**: 输出保持机器可解析和可追溯，不退化为主观判断。

### Stage Plan

M3 分为三个阶段推进：

| Stage | Goal | Status | Exit Criteria |
|-------|------|--------|---------------|
| M3.1 evidence fact upgrade | 建立高置信真实 case 验证集，并从漏报 case 中补足可静态验证的 direct evidence | closeout-ready | 40-case frozen eval v1 complete；新增 evidence 在真实 case 上命中且负例不过度误报 |
| M3.2 confidence evidence | 给每条 fact evidence 标注置信度和证据价值，方便 AI 后续独立分析；不生成面向人的语义化结论 | active | evidence 输出包含 confidence/value；weak evidence 明确标为 supporting/context；不新增 `Semantic findings` |
| M3.3 closeout benchmark | 用 frozen eval 重新评估 v0.2.0 产品效果，决定是否进入 release closeout | planned | 重新跑 40-case benchmark，报告 precision/actionable/missed/weak-only 变化和失败类型 |

M3.2 不继续以堆 detector 为主目标，也不生成面向人的语义化输出。新的 detector 只有在 frozen case 暴露明确、可迁移、可验证的缺失事实时才加入；否则优先提升证据的置信度、价值标注和机器可解析性。

### Risk Signal Targets

M3 不以“修复某几个已知 case”为目标，而是从高置信风险记录中抽象可迁移的风险信号。当前第一批 seed 来自 374 个 merged PR 候选、34 个 enriched 候选和 12 个严格筛选的高置信风险记录，记录在 `eval/semantic-candidates/selection-report.md`。

M3.1 将测试资产分成两套，避免用开发题库证明产品价值：

- dev set: `eval/risk-signals/dev-cases.toml`，至少 32 个 synthetic / reduced-real case，用于 TDD 和开发回归；每类 signal 至少 positive / negative / boundary 覆盖。
- holdout set: `eval/risk-signals/holdout-v1.toml`，阶段 gate 保留集；只在阶段收尾时使用，不用于同一 sprint 内调 detector / wrapper / prompt。
- eval candidates: `eval/risk-signals/eval-candidates.toml`，只收真实 PR/commit；当前 frozen v1 已有 40 个 `freeze_ready` case，其中 26 个来自首轮 seed，9 个来自 frozen-fill A 严格复审，5 个来自 frozen-fill B 严格复审。
- frozen pilot v1: `eval/risk-signals/frozen-pilot-v1.toml` 固化 26 个高置信 case，用于 M3.1 semantic-flow 开发和 20-case benchmark smoke；这不是完整 frozen eval v1，不用于声明产品价值。
- runner corpus: `eval/corpus/risk-signal-pilot.toml` 与 frozen pilot 保持同序；`eval/corpus/risk-signal-frozen-v1.toml` 与 frozen v1 当前 seed 保持同序。两者都可通过 `DECAY_EVAL_CORPUS=<corpus> eval/scripts/run-semantic-case.sh <case-id>` 执行。
- frozen eval v1: `eval/risk-signals/frozen-v1.toml` 定义产品效果验证集，目标 40 个真实 case；`eval/risk-signals/frozen-v1-design.md` 记录准入门槛和排除项；当前状态为 `complete`，已有 40 个 high-confidence seed。冻结后不得为适配工具表现而替换样本。
- closeout eval v2: v0.2.0 closeout 前目标 60 个真实 case，用于提高结论置信度。
- validator: `eval/scripts/validate-risk-signal-pack.py` 保证 signal、dev set 和 eval candidates 字段完整、source refs 可追溯、signal 分布不过窄。

语义层要优先识别以下 8 类信号：

| Signal | What It Means | Example Source | Expected Finding Shape |
|--------|---------------|----------------|------------------------|
| 隐含假设增强 | diff 新增、修改或依赖了更强的前置条件，但边界保护不足 | panic on timeout=0、closed channel buffer assertion、invalid UTF-8 RawValue | 指出被加强的假设、触发边界、相关代码事实和需要补的边界测试 |
| 非主路径变更 | diff 触碰 error、invalid input、fallback、cleanup、shutdown、closed 状态等低频高影响路径 | invalid content-length、invalid chunk size、socket error readiness | 说明非主路径如何被改动，以及为什么 happy path 证据不足 |
| 状态转换变更 | diff 改变状态机 transition、terminal state、error recovery、wakeup condition | HTTP parser recovery、graceful shutdown、readiness mask | 标出状态变量/条件变化、前后状态关系和 reviewer 应检查的不变量 |
| 错误传播链变更 | diff 改变底层错误如何 surfaced、mapped、ignored、defaulted 或 early-returned | UDP `SO_ERROR` 未 surfaced | 说明错误来源、传播断点、调用方可见行为和测试需求 |
| 生命周期顺序变更 | diff 改变 create/hold/drop/close/shutdown/upgrade/cancel/spawn/join 的顺序关系 | upgraded connection 后 graceful shutdown panic | 标出资源生命周期阶段、顺序变化和可能的 use-after-close / double action / missing cleanup |
| 并发时序变更 | diff 修改共享状态、锁、channel、waker、task handoff、thread pool shutdown 的 happens-before 约束 | blocking pool shutdown race | 说明共享状态和时序假设，并要求 loom/concurrency/regression evidence |
| 外部契约变更 | diff 改变 public API、feature flag、default config、dependency behavior、serialization/CLI/protocol contract | `yaml-rust` upgrade causing API break | 说明契约面、兼容性影响和迁移/回归证据缺口 |
| 风险路径测试缺口 | diff 触碰上述风险路径，但测试没有覆盖对应边界、平台、并发或协议场景 | branch coverage missing、regression test added only after bug | 把风险事实和测试事实绑定，输出缺失的具体测试类型 |

这些信号不是合入裁决。M3 输出必须保持为给 AI 消费的证据：说明事实类型、置信度和证据价值，不声明“这一定是 bug”。

### Go/No-Go Criteria

| Dimension | Criterion |
|-----------|-----------|
| Output | `diff` prints fact evidence with confidence/value labels |
| Traceability | every labeled evidence keeps category/kind/source/file |
| Weak signal handling | weak-only signals are labeled supporting/context, not direct |
| Benchmark | frozen eval v1 rerun reports precision/actionable/missed/weak-only deltas |
| Quality | `cargo fmt -- --check`, `cargo test`, `cargo clippy -- -D warnings` pass |
| Scope | `doctor` hot debt remains deferred |

### M3.2 Decision Path

- **Pass**: every evidence item carries confidence/value labels, and frozen eval replay can distinguish direct evidence from supporting/context evidence.
- **Fail**: if weak facts are still indistinguishable from direct facts, do not add external context; fix evidence labeling first.

### Risks

- Confidence labels become unverifiable subjective judgement.
- External context masks weak fact evidence.
- Bad-case rules overfit the first 12 high-confidence seed records instead of learning transferable signals.
- Negative-control silence regresses.

M3.2 active plan:

1. Add confidence/value labels to each raw evidence item.
2. Use labels to distinguish:
   - `direct`: current diff directly changed a risk mechanism;
   - `supporting`: useful only when paired with direct evidence;
   - `context`: background signal that should not drive conclusions alone;
   - `coverage_limit`: tool confidence limitation.
3. Keep `decay` output as evidence, not judgement:
   - no `Semantic findings` section;
   - no generated `claim`;
   - no merge recommendation;
   - no bug assertion.
4. Let downstream AI use confidence/value labels to compose its own analysis.
5. Validate labels with frozen real cases and negative controls before claiming product improvement.

### Frozen Eval v1 Completion Rule

Any future replacement or expansion case must pass the same gate as the pilot:

1. screen a broad candidate pool before looking at decay output;
2. enrich PR, issue, review, test, and follow-up context;
3. run independent ground-truth / risk-signal / skeptic review;
4. reject cases that are only performance, macro, build-only, revert-only, or disputed-fix evidence unless their signal track is explicitly added;
5. update `eval-candidates.toml`, `frozen-v1.toml`, and `risk-signal-frozen-v1.toml` together.

If a frozen case is later invalidated, v1 must return to `building` until a replacement passes this gate. The correct action is to collect more sources, not lower the gate.
