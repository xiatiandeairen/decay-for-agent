# M3 — v0.2.0 语义筛选证据层

## 1. Goal

### Definition of Done

`decay` 能在事实证据层之上输出语义筛选后的可复查 review 证据：

- `diff` 场景：从 complexity / stability / quality / semantic-pattern / history 等事实 evidence 中筛选出真正值得 reviewer 优先看的价值证据。
- `doctor` 场景：0.2.0 暂不作为主线；等 `diff` 语义筛选通过 benchmark 后再恢复 hot debt 规划。

v0.2.0 不做“是否可合入”的主观裁决，也不输出 merge recommendation。语义层只能把事实证据组合、降噪、排序和解释；每个结论必须能回链到 source。

### Value Target

作者在 review 任意 PR 时，不再只看到扫描命中列表，而是能看到带来源、带可信度边界的 review 证据：

- 哪些事实证据直接说明本次 diff 改变了行为边界、稳定性边界或 API/协议承载面。
- 哪些只是 supporting context，不能单独作为 Top risk。
- 当前 top review evidence 为什么可信、还缺什么上下文、reviewer 下一步该检查什么。
- 每条语义结论都能追溯到 source，例如 diff hunk、AST snapshot、git history、decision docs、issue/PR/review/CI metadata 或 human judgement。

### Key Hypothesis

- **Hypothesis A**: `decay diff <git-ref>` 的语义筛选层能把 0.1.1 的事实 evidence 收敛为更高价值的 Top risk，减少弱扫描信号污染和高价值漏报。
- **Type**: business value
- **Validation method**: 使用预注册高质量 PR benchmark。以 0.1.1 的 10-case 结果作为 baseline：`precision_at_top3=65%`、`actionable_pr_rate=60%`、`missed_high_risk_count=2`、`noise_top3_count=3`。0.2.0 第一轮 20-case 目标：`precision_at_top3 >= 75%`、`actionable_pr_rate >= 70%`、`negative_control_silence_rate >= 90%`、`missed_high_risk_count <= 1`、`weak_only_top_risk <= 2`。

- **Hypothesis B**: 语义层能保持事实层的可复查性，不退化成不可验证的 AI 自评。
- **Type**: business value
- **Validation method**: 每个 Top risk 必须包含 `claim`、`supporting_facts`、`source_refs`、`confidence_reason`、`limitation`、`review_action`；人工 judgement 可以独立复核。无法回链到事实 source 的结论不得进入 Top risk。

## 2. Plan

### Planned Deliverables

- done: 0.1.1 fact evidence layer，覆盖 complexity / stability / quality / scanned semantic patterns / history / local evidence DB。
- done: 10-case 外部 PR benchmark，暴露静态扫描的价值边界：强项是默认值/配置/显式危险构造/负样本静默；弱项是 API/protocol 行为语义、高价值漏报、弱信号进入 Top risk。
- planned: semantic evidence schema，新增 `claim`、`supporting_facts`、`source_refs`、`confidence`、`limitation`、`review_action`。
- planned: semantic ranking，强证据优先，弱信号默认降级为 context；只有与直接 diff evidence 绑定时才提升。
- planned: bad-case scenario pack，覆盖 API surface、protocol behavior、behavior gate/config boundary、move/refactor suppression、negative controls。
- planned: optional external context ingestion，优先 PR title/body/review comments/linked issue/CI failure；默认 opt-in，所有外部上下文保留 source。
- planned: local evidence DB 扩展，记录 semantic findings、fact-to-claim links、judgement feedback。
- planned: 20-case benchmark runner 和 report，比较 0.1.1 fact-only 输出 vs 0.2.0 semantic-filtered 输出。
- deferred: `doctor` hot debt evidence 输出，等 diff 语义层通过第一轮 benchmark 后再做。

### Go/No-Go Criteria

| Dimension | Criterion |
|-----------|-----------|
| Functional completeness | `diff` 能输出 semantic-filtered top review evidence，并保留底层 fact evidence（team agreement） |
| Functional completeness | 每个 semantic finding 都能回链到 supporting facts 和 source refs（team agreement） |
| Quality | `cargo test` 和 `cargo clippy -- -D warnings` 通过（team agreement） |
| Evidence traceability | 不允许无 source 的语义结论进入 Top risk（team agreement） |
| Product benchmark | 20-case benchmark 达到 precision@top3 ≥75%、actionable ≥70%、negative silence ≥90%、missed high risk ≤1（target） |
| Performance and stability | 在 mxcore-proposal 规模项目上 evidence 生成可在本地交互式使用；具体阈值待首次实现后实测（pending data） |
| Security | 默认只读本地 git、源码、docs 和本地 SQLite；外部 issue/PR/CI 数据源必须显式 opt-in（team agreement） |
| Maintainability | fact collection、semantic selection、storage、presentation 分层；不把语义规则散落在 CLI print 中（team agreement） |

### Estimated Effort

no data（v0.2.0 范围显著大于 v0.1.1；需要在第一轮 semantic vertical slice 后补充估算）

### Decision Path

- **Pass A**: 20-case benchmark 达到目标，且人工能独立复核 semantic finding 的 source chain 后，再考虑更大样本和 agent-facing 输出。
- **Fail A**: 若 Top risk 仍主要由 weak signals 构成，或 missed high risk 没下降，暂停新增外部数据源，先修 semantic ranking 和 bad-case tests。
- **Pass B**: 如果语义层能稳定提升 `diff`，再恢复 `doctor` hot debt 规划。
- **Fail B**: 如果语义层输出无法复核或依赖主观推断，回退到 fact-only 输出和 value_note，不进入 0.2.0。

### Risks

Dependencies: 稳定 fact evidence schema、git diff/function range mapping、function identity、本地 SQLite schema 演进、可复跑 PR benchmark、真实 judgement 数据。

Risks:

- 语义层可能变成“看起来聪明但不可验证”的 AI 自评。
- 过早接入 PR/issue/CI 可能让外部上下文噪声掩盖事实证据。
- 针对少数 bad case 写死规则可能提升局部指标，但不能泛化到 20-case benchmark。
- 弱信号如果仍然能单独进入 Top risk，会继续破坏用户信任。
